# NQ Train E development material v1

On 2026-10-17 all 74,097 C1 items were ingested, and the first batch fixed 100 records pending review (80 with EM=0 and the reference passage hit in the candidates, 20 EM=1 controls). The full set is saved in a locally ignored directory; 100 is the review batch size. The screening condition is not a diagnosis label, and all human fields are pending review.

The "pending review" in the previous sentence describes the frozen original package. After batch 6 on 2026-10-19, all 100 items have been looked through in the first round: 75 finalized (11 internal E targets, 64 correct controls), 25 pending, 0 not looked through; see [review record](../../../docs/ANSWER_REPAIR_NQ_TRAIN_REVIEW_20261017.md). The [original 92-item review page](review/NQ_train_pending_92.html) keeps the same package scope; you can manually import the [cumulative chat state of batch 6](review/NQ_train_pending_92.chat_confirmations_batch06_20261019.json), which shows 67 confirmed, 25 pending and 0 blank on this page; the other 8 earliest confirmed samples were never on this page. Importing replaces the page's local draft, so reviews in other browsers should be exported as a backup first. The exported [cumulative development list](../../../configs/splits/answer_repair_nq_train_confirmed_dev_v6.json) contains 75 compatible inputs; the 25 remain isolated, and none have become new experimental results.

This directory has no GPU repair results. For the v8 new implementation and experiment package see the [v8 notes](../../../docs/ANSWER_REPAIR_V8.md); there are no new GPU results yet. `preflight.json` only records that the existing v7 strategy read the inputs successfully, completed=0.

For details see [ingestion notes and reproduction steps](../../../docs/ANSWER_REPAIR_NQ_TRAIN.md). The review entry points are the [TXT index](review/review_queue.txt) / [JSONL with evidence and offline references](review/review_queue.jsonl), all from the E internal development part. The E internal held-out part has not yet established team-wide unseen status.

`preparation.json` records input and queue hashes; the frozen config it references additionally records the source shards, source audit and selected IDs. Assisted judgments and user confirmations are saved separately under `data/annotations/`, preserving the original bytes of this package. Review of old v7 outputs continues to use the original queue.
