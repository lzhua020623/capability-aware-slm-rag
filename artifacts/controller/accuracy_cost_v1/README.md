# NQ 准确率—成本回放实验（2026-10-31）

这次完成了现有策略的逐题回放和成本核算，没有新增 GPU 推理、判官调用、训练或生产配置变更。完整产品相对普通 RAG 仍然是增效但增本；相对固定 8 上下文选择器，已有结果支持“质量接近、生成调用更少”。但相对固定 5 上下文选择器，节约非常小，不能笼统宣称胜过所有固定增强。

## 1. 数据与边界

- **质量主表：NQ Test 11,114 题。** 复用冻结 C1、B 路由、B+BM25、全部已登记的选择器策略。另从原候选及生成记录重建每题的 P3-20 答案，补齐 P3-on-all 对照。23 个表项包括一个与当前产品完全相同的参数别名；绘图只画一次。
- **确认集：2,440 题。** 同样回放冻结策略，见 `strategy_table.csv` 和 `pareto_confirm.pdf`。确认集已反复使用，不是新的独立测试。
- **在线计时：上述确认集中的 300 题。** 原日志在 RTX 5090 D 上按单题执行，先热身 10 题。C1、B+BM25、最终答案全部与确认集已归档结果一致（300/300）。不把 300 题耗时与 Test 准确率视为同批实测。
- **标签不修改。** 沿用既有 judge-assisted 口径及标签优先级；新增归档的 P3 判官记录只填缺失答案对；Test 中团队 RAG 标签最后优先。所有方案均有完整标签，未知不按错误处理。此前 100 题助手审核没有覆盖这些标签。
- **Test 已曝光。** 本次是历史结果的描述性二次分析，不是新盲测；所有比较点此前已经固定，不根据这次 Test 结果换生产策略。点估计 Pareto 前沿只用于展示。
- B 指当前 **P60 + correct-gate（p_fail ≥ 0.39）及动作映射** 的组合，不把 B 的全部收益单独归因于 P60。

## 3. 是否比无差别增强更值得花计算

下面 Δ 为“前者减后者”。区间由同一道题的正确性差值配对 bootstrap 得到，10,000 次，固定随机种子；不是把两个准确率区间独立相减。总调用节约与选择器局部节约分开。

| 配对比较 | Δ准确率（百分点） | 配对 95% 区间 | 总生成调用减少 |
|---|---:|---:|---:|
| B 对所有题 P3 | +0.072 | [−0.270, +0.414] | **21.62%** |
| 完整产品对固定 8 选择器 | −0.090 | [−0.207, +0.027] | **22.97%** |
| 完整产品对固定 5 选择器 | −0.198 | [−0.486, +0.090] | **1.51%** |
| L 对固定 8 投票 | +0.027 | [−0.432, +0.468] | **53.43%** |
| L 对固定 3 选择器 | −0.225 | [−0.612, +0.171] | **21.17%** |
| M 对固定 3 选择器 | +0.054 | [−0.288, +0.387] | **8.79%** |
| M 对完整产品 | −0.441 | [−0.747, −0.126] | **30.05%** |
| θ=0.2、τ=0.8 对完整产品 | −0.171 | [−0.297, −0.054] | **7.19%** |

解释：

1. **早停相对固定 8 选择器有实质节约。** 完整产品局部选择器调用减少 31.79%；计入共同的 C1/B/BM25 后，总生成调用减少 22.97%。在现有标签和样本下，质量差的区间约在 −0.21 至 +0.03 个百分点。
2. **不能只拿投票做弱对照。** L 相对固定 8 投票节约很大；对更强、也更便宜的固定 3 选择器，它低 0.225 个百分点，区间允许超过 0.5 个百分点的下降。M 对固定 3 选择器点估计质量略高、调用略少，但没有证明质量显著更好。
3. **完整产品不是普遍最优。** 固定 5 选择器在 Test 上质量更高、调用只略多；在确认集上则完整产品更高（71.967% 对 71.107%）。这正是不能按 Test 换策略的原因。
4. **低成本档要接受质量代价。** M 相比完整产品少约 30% 总调用，但点估计少答对 49 题。不能把“低成本”写成没有质量损失。
5. **普通 RAG 仍最便宜。** 完整产品相对匹配 C1 修好 923、改坏 348，净 +575（+5.174 个百分点，95% 区间 [+4.553,+5.785]），代价是总生成调用增加为 4.704 倍。

`summary.json` 同时给出 11 个预列比较的精确 McNemar p 值和组内 Holm 校正。不能用“p 不显著”证明等价。本次额外给出的单侧 95% 下界与 0.5/2 个百分点容许损失只作描述性敏感性阅读，不构成预登记非劣检验；bootstrap 区间也不是多重比较同时置信区间。

## 4. P3 阶段的节约究竟是多少

同一批 Test 上，B 触发 P3 的题数为 6,166/11,114（55.48%），比所有题触发少 44.52%。其中 Top-5 未变的题无需重答：

- B 实际 P3 生成 **6,070** 次；所有题 P3 实际生成 **10,810** 次，少 **43.85%**。
- 加上共同的 11,114 次 C1，总调用从 **21,924** 降到 **17,184**，少 **21.62%**。
- 正确题数从 **6,624** 到 **6,632**，点估计 +8，配对区间跨 0。

这是**调用层面的节约**。B 增加了 Diagnosis/P60 特征等开销，不能仅凭这些计数断言相对 P3-on-all 的端到端延迟也降低 21.62%；后者没有匹配的全程计时。

## 5. 延迟：把已测事实与前缀估算分开

原 300 题在线计时回放如下。这些质量数字也取自这 300 题，不使用 Test 的准确率。

| 配置 | 本批准确率 | 均时 | P95 | 生成/题 | 输入 token/题 | 性质 |
|---|---:|---:|---:|---:|---:|---|
| C1 | 66.667% | 0.241 s | 0.428 s | 1.000 | 734 | 同一次运行的实测前缀 |
| B+BM25 | 71.667% | 1.364 s | 2.976 s | 1.643 | 1,239 | 同一次运行的实测前缀 |
| 完整产品 | 73.667% | 2.688 s | 4.616 s | 4.683 | 3,746 | 实测全程 |
| L：θ=0.39，τ=0.6 | 72.333% | **约 1.934 s** | 见 JSON | 2.700 | 2,109 | 两次运行的分量/前缀估算 |
| M：θ=0.3，τ=0.6 | 73.000% | **约 2.136 s** | 见 JSON | 3.143 | 2,479 | 两次运行的分量/前缀估算 |
| θ=0.2，τ=0.8 | 74.000% | **约 2.505 s** | 见 JSON | 4.267 | 3,417 | 两次运行的分量/前缀估算 |

完整产品均时构成：C1 0.241 s、Diagnosis 0.0175 s、Controller/P3/BM25 1.1055 s、答案选择 1.3232 s，另有约 0.0009 s 未归入上述阶段的开销。答案选择占实测全程 **49.2%**。`latency_measured.pdf` 同时显示分量均值和全部 300 题的经验累积分布，未隐藏长尾。

**估算方法与限制：** 对每题先用已冻结策略决定是否进入和何时停止，再取 2,440 题完整产品日志中实际执行的相应前缀生成耗时，保留全部该题选择器非生成开销，加上 300 题运行中实测的 C1/Diagnosis/Controller 时间。未进入则选择器耗时为零。完整产品自身的这种估算为 2.680 s，接近实测 2.688 s，只是均值一致性检查，不是对所有反事实策略的独立验证。固定 5/8 对部分题需要尚未计时的后续上下文，因此不补猜延迟。

- 新低成本策略**没有在线执行**，1.934/2.136 s 必须标“估算”，不能写成实测。
- 不同上下文数量仍使用预先取得的 BGE top100 + BM25 top50 及交叉编码器评分；少生成不等于按比例减少全部检索/评分开销。
- 300 题不是新的选型集，不能因其中 θ=0.2 的质量略高就更新策略。
- 当前结果没有证明“1.5 秒达到 Test 约 62%”。更不能把低成本策略的 Test 质量与另一个批次的估算延迟当成同批实测点。
- 模型加载 82.19 s、离线索引构建、训练/判官及数据预计算均不计入逐题在线延迟；不含并发吞吐、冷启动或付费模型价格。
- 2,440 题中有两题因排序近似平局导致在线各多生成一次；现有归档的答案等价检查通过。主表保持原冻结回放计数，在线成本保持实际计数，两者不强行改成一样。

## 6. 可写入报告的结论

> 在固定 Qwen2.5-7B 与匹配 C1 输入下，完整产品在 NQ Test 的 judge-assisted 准确率提高了 5.17 个百分点，平均生成调用增加至 4.70 次。相对固定 8 上下文选择器，冻结的早停策略减少了 22.97% 的总生成调用，质量差为 −0.09 个百分点，配对 95% 区间为 [−0.21,+0.03]。低预算门控进一步提供了质量与计算量之间的折中。该结果支持相对部分固定增强策略的计算效率改善，但不支持比普通 RAG 更便宜、比所有固定增强更好，或端到端货币成本下降的主张。

这是有反例、有区间的已有策略回放证据，强于只列“完整产品 62.76%”。局限是 Test/确认集已多次使用，判官标签本身也有误差；区间只反映题目抽样，不反映判官误判、训练/策略选择不确定性或硬件时间波动。

后续若只允许补一次小实验，应在独立的计时题上固定 L 或 M 之一，实跑其端到端路径验证估算；不要根据当前 Test 改阈值。本次不增加该 GPU 作业，也不更换生产默认配置。

## 7. 复现与文件

```bash
python scripts/analyze_accuracy_cost.py
python scripts/plot_accuracy_cost.py
python -m unittest tests.test_accuracy_cost
```

需现有项目依赖；绘图另外使用 matplotlib、numpy、Pillow。分析不需要 GPU、API 密钥、原始全库索引或暂存目录。

- `method.json`：分析范围、比较列表、成本/统计口径；属于已有结果二次分析的记录，不冒称事前实验注册。
- `input_hashes.json`：冻结所有输入归档与策略的 SHA-256，改变即拒绝回放。
- `inputs.tar.gz`：原 300 题计时、原计时代码/清单、2,440 题精简成本事件、11,114 题成本及 P3 重建结果、缺失 P3 答案对的原判官结果、原始来源哈希。预处理时检查原 Test/确认集结果 SHA 与已有归档一致。
- `paired_records.jsonl.gz`：所有策略逐题答案、判官分数、相对 C1/基底的分差、总调用、额外调用、停止阶段。
- `summary.json` / `strategy_table.csv`：全部结果、区间、修复/误修、成本、Pareto 点集及批次说明。
- `timing_replay.jsonl`：逐题实测或估算成本，逐项标记性质。
- `pareto_test.*` / `pareto_confirm.*`：相对 B+BM25 的质量增益与总调用；不把离散策略连接为连续可实现曲线。差值轴有明确零线，不使用截断的准确率柱图。
- `latency_measured.*`：300 题在线测量分解及分布。PDF/SVG 为矢量，PNG 为 300 DPI。
- `data_profile.json` / `figure_qa.json`：绘图数据剖析与版面检查。
- `scripts/prepare_accuracy_cost_inputs.py`：仅用于从历史暂存数据重建输入包；常规复现不需要执行。
- `tests/test_accuracy_cost.py`：完整归档回放、缺标拒绝、输入篡改拒绝、配对统计、缓存/前缀核算、批次与实测/估算区分。

补充交叉核对：工作期间新增的 `final_evaluation_v1` 归档与本实验的 300 题计时原始字节一致，11,114 题 C1/P3/B+BM25/路由逐题一致。本实验新增的是总调用口径、完整策略前沿、低成本前缀估算及更强固定选择器对照；没有修改那份归档。

输入数据、策略文件和分析口径按原始字节校验；被引用的 Python 算法代码另按 LF 规范化后封存，避免同一代码仅因平台换行产生假差异。这个处理不改变任何训练/评测数据边界文件的哈希。
