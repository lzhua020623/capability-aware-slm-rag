# FEVER 可恢复性：真实检索与理想证据（FEVER train 研究集，2026-10-31）

登记 `configs/controller/fever_recoverability_v1.json`（commit 8aa64a7），样本见 `../sample/`。固定 Qwen2.5-7B，在 FEVER train 的 SUPPORTS / REFUTES 声明上比较：
C0 不给证据、C1 BGE 前 5、L1 每题做 P3（产品的 P3 检索增强）、L3 标准证据句放第 1 位加 C1 的其余页面、L4 只给标准证据句。按标签精确比对，不用判官。

**只做研究，不是 FEVER 产品评测。** 团队 FEVER Test（fever_dev 13,332 题）没有运行；这里的数字不用于任何产品选择。

全部 2000 题：C1 84.7%，L4 92.5%；五个条件都没有无法解析的输出。完整证据页面出现在 C1 前 5 中 1304 题，做完 P3 后 1358 题。

## 读法

- 理想证据（L4）能救回约 72% 的 C1 失败，和 NQ 扫描集（`artifacts/controller/recoverability_oracle_v1`，L4 RFR 72.6%）接近；真实检索增强（L1）只救回约 14%，全部 2000 题上相对 C1 净 -9（44 / 53）。两个任务的数据、评分方式不同，这种相似只是跨任务观察，不证明失败机制相同。
- L3 的恢复率比 L4 低 25.5（开发集）和 30.5（留出集）个百分点：同样的证据句，加上检索来的其他页面就明显变差。
- 只有两个标签，换输入就可能偶然翻转标签，所以"错→对"要和"对→错"一起看：C0 不给任何证据也"救回"约 31%，但同时改错更多。
- C1 的错误集中在 SUPPORTS：模型倾向判"反驳"。
