## 4. Diagnosis / B 路由消融（P60 + correct-gate）

| 集合 | 送去 P3 的题 | C1 | P60 路由 | 全部送 P3 | 随机同样多（净，均值 [95% 区间]） | 没路由的题若也送 P3 |
|---|---:|---:|---:|---:|---:|---:|
| 扫描集 | 3013 / 6000（50.2%） | 65.07% | 66.72%（净 +99，239 / 140） | 66.47%（净 +84） | +42 [+18, +66] | -15（91 / 106） |
| Test | 6166 / 11114（55.5%） | 57.59% | 59.67%（净 +232，497 / 265） | 59.60%（净 +224） | +124 [+92, +156] | -8（183 / 191） |

| 集合 | p_fail 预测 C1 答错的 AUC | 在 C1 答错的题里预测"P3 能修好"的 AUC |
|---|---:|---:|
| 扫描集 | 0.71 | 0.51 |
| Test | 0.68 | 0.53 |

- 表中"P60 路由"指 B 的完整路由：P60 选出的题，加上诊断判为正确但 stage-1 p_fail ≥ 0.39 时由 correct-gate 放行的题（`configs/controller/quality_adaptive_v1.json` 的 `correct_gate`）。消融衡量的是这套路由整体，不单独归因于 P60。
- 这套路由只送约一半的题，净收益不低于全部送 P3，且远高于随机挑同样多的题（5,000 次随机抽取全部低于它）。
- p_fail 是失败风险分数，不是可恢复性分数：在已失败的题里它几乎分不出哪些能被 P3 修好。报告中应称为风险路由，不能写成 p_recoverable。
- BM25 规则只用于被路由的题时 Test 准确率 60.62%，对每题都用时 60.52%。
- 扫描集是验证集（所有扫描选择都在上面做过）；Test 上未路由题的 P3 / BM25 答案此前没有判官标签，由本次 p60_test 批次补齐（11,114 题全部有标签）。

## 5. 实测成本（确认集 300 题，NVIDIA GeForce RTX 5090 D，线上路径一次一题）

| 方案 | Test 判官准确率 | 每题延迟（秒，均值 / 中位数 / p95） | LLM 调用 / 题 | 输入 token / 题 |
|---|---:|---:|---:|---:|
| RAG（C1） | 57.59% | 0.24 / 0.22 / 0.43 | 1.00 | 734 |
| B+BM25 | 60.62% | 1.36 / 1.73 / 2.98 | 1.64 | 1,239 |
| 最终产品 | 62.76% | 2.69 / 2.64 / 4.62 | 4.68 | 3,746 |

各阶段平均：C1 检索 0.07 秒、C1 生成 0.17 秒、诊断 0.02 秒、控制器 1.11 秒、答案选择 1.32 秒。
被路由的题每题 3.76 秒，未路由的 1.59 秒；样本中路由比例 50.7%（Test 为 55.5%）。
答案选择在第 3 / 5 / 8 阶段停止时分别为 1.06 / 1.30 / 1.73 秒。
B+BM25 的延迟是同一次运行中去掉答案选择阶段的部分。预热 10 题后计时；模型加载（约 82 秒）只发生一次，不计入。这 300 题的 C1、控制器和最终答案与确认集产品运行逐题一致。

## 披露

- **Test 使用：** 这次只做评估：置信区间、已登记策略之间的比较和 P60 消融。没有改动任何阈值、策略或设置。Test 此前已被路线 1、BM25 规则和自适应选择使用并逐题分析过。
- **确认集使用：** 只用 300 题测延迟，不评分。
- **判官：** p60_test 批次 370 行，团队判官代码未改动；EM 结论不依赖判官（第 2 节）。
- **计时代码：** 计时脚本在服务器的 `code_adaptive` 副本上运行，即确认集等价检查用的同一份代码，文件哈希见 `provenance.json`。
- **数据边界：** GPU 主机只收到问题；金答案只在本地使用。
