## 披露

- CPU 线程：重排器和检索的查询编码器在 CPU 上运行。本次设为 OMP/MKL 16 线程；确认集运行时是 torch 默认的 64 线程，在 16 核配额下慢约 10 倍。用户批准这一改动，只为缩短运行时间。用 16 线程把确认集 2,440 题完整重跑一遍：最终答案 2440/2440 相同，C1 答案、Diagnosis、动作全部相同。只有 1 题的 C1 Top-5 互换了两条几乎相同的段落（分数都是 0.5869786），答案不变。P3 分数 1164/1206 逐位相同，最大差 9.9e-4。
- 判官：团队 `run_llm_judge.py`（`origin/feature/baseline-evaluation`，未改动）。需要的（题目，答案）组合中，团队 Test 判官文件（无检索 Qwen、产品、RAG）已判过的直接复用标签。其余 1,970 个组合中，1,644 个调用了 API，部署为 elec5623-e-teacher-sol-v1，无失败；326 个是自动匹配。团队文件的判官是 gpt-6.1-sol。自动匹配或判为 CORRECT 算对，UNCERTAIN 不算对。
- 标签顺序：同一答案有多份标签时，以团队 RAG 基线的为准（用户规则）。团队判官在 RAG 和产品两次评测中，对 10,561 个相同答案中的 95 个给出了不同结论。如果改为本轮新判的标签优先，有 94 个组合的标签会变：本轮相对 C1 的净值为 +226，相对产品和 RAG 的净值不变。
- 金答案在本地从团队交付的 `annotation_reference.gold_answer` 导出，与团队判官文件 11,114/11,114 一致，没有发到 GPU 服务器。
