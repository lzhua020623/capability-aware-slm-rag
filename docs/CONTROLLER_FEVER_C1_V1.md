## Controller path

`--fever-resources configs/controller/fever_resources_v1.json` explicitly loads the original IVFPQ, IDs, offsets and corpus, and validates the hash chain of the original package/full ordering/structure/query replay. NQ and FEVER backends are dispatched strictly by dataset; the NQ Train index cannot be used for FEVER.

FEVER executes per T1: original claim Top20 → fixed reranker → equal-weight RRF(k=60) → Top5 → re-answer with the original FEVER C1 prompt. NQ's original default API continues to support only NQ, and FEVER must be enabled explicitly; the formal runner's FEVER adaptive/always_retrieve errors out early when resources are missing, and a missing-resource fallback is not counted as implementation coverage.

FEVER accepts SUPPORTS/REFUTES parseable by the existing parser, and saves the raw generated text; if unparseable or the provider errors, the answer entering the stage is kept. NQ's original span grounding rule is not used for FEVER binary labels. A parseable label does not prove the judgement correct; that still requires independent evaluation. A fixed Qwen is used here, with no NLI or new prompts introduced.

```bash
python scripts/run_controller_integration.py \
  --input /path/to/fever_development_runtime.jsonl \
  --fever-resources configs/controller/fever_resources_v1.json \
  --preflight --output-dir /path/to/new_preflight
```

When executing both datasets mixed, additionally provide `--nq-resources configs/controller/nq_train_resources_v1.json`. Until the new C1 runtime is generated, query-only c1_tasks cannot be passed off as Controller input.
