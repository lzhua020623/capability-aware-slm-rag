The single-call constraint described below refers to the v4 baseline; the v5 review strategy makes at most two calls, with cost recorded separately.

The version history is kept below: v1's real smoke on 10 FEVER samples produced 8 `invalid_output` and 2 `insufficient_evidence`; the correct count was still 7/10 with no answer changes, after which expansion of that version was stopped.

The first-round raw results, model audit, and Codex offline qualitative review are saved in `artifacts/answer_repair/v1/colab_20261013_smoke/`. The review is not human annotation, nor a runtime semantic verifier. The independent model audit verified the actual Qwen2 architecture, 196 NF4 layers, FP16 compute, and double quant; allocated GPU memory after model loading was about 5.56GB, which is not the full inference peak. Transformers 5.18 does not provide `_commit_hash`/`hf_device_map` for this loaded object, so v2 explicitly pins the observed snapshot `a09a35458c702b33eeacc393d103063234e8bc28` and verifies the actual quantized layers. The historical C1 did not record a revision, so the historical environment cannot be claimed to be fully identical.

The historical `v2_contract_last` keeps the same evidence, one call, and the 384-token cap, places the decision rules at the end of the input, provides a keep template with the current original answer and a complete insufficient empty-value template, and emphasizes short quotes and real ranks; parsing, labels, and citation checks were not relaxed. `repair` must change the answer; the same answer must use `keep`. Historical experiment packages are kept; code changes get a separate version package.

v2 completed 10 samples each of FEVER/NQ and the corresponding Reanswer comparisons, with no accuracy gain in either; Verify invalid was FEVER 3/10, NQ 8/10. v3 added fictional examples for the three decisions, required first finding the fact the query asks for before comparing with the initial answer, and stopping at a complete JSON object. Real v3 on 10 samples each still had no answer changes, with invalid FEVER 5/10, NQ 6/10.

v4 keeps the Verify prompt of `v3_balanced_examples` and fixes the token boundary: in a few cases the last BPE token contains both the JSON closing brace and an extra backtick; the stopper records that actual boundary and passes only the complete object to the strict parser. `raw_output` saves the full output, and `validation_input` records the object text when the two differ; fields, citations, and answers are not modified. The ordinary parser still rejects any trailing text. The Reanswer comparison does not use the JSON stopper.

v4 also has `--strategy grounded_reanswer` (`v4_candidate_first`): the model sees only the query and the original Top-5 and generates answer/citations without seeing the initial answer; the program then derives keep/repair based on whether the candidate equals the original answer, and applies the same citation rules. The purpose is to test whether anchoring on the original answer limits repair; it is still one call of the same model, introduces no reference answer, and cannot serve as independent semantic verification. This strategy has been run on the fixed 50-sample development set; results, raw outputs, and review are saved separately.

v3 citations are matched by whole-word and punctuation tokens, ignoring spaces on both sides of punctuation and keeping every word and punctuation mark. `Paris , not London .` and `Paris, not London.` can match; deleting a comma or negation word, substituting words, changing the citation number, or cutting York out of Yorkshire are all disallowed. Different quote/bracket styles are still not automatically replaced. This only fixes formatting differences and does not provide a semantic support verdict.
